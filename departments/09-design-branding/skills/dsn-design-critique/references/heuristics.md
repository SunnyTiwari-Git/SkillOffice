# Usability heuristics

A checklist in the spirit of the widely used ten usability heuristics (Jakob Nielsen), written in our own words. Use it to find problems; report each as a finding with a fix.

1. **Show what is happening.** The system gives timely feedback: loading, saving, success, failure.
2. **Speak the user's language.** Words, icons and order match how users think, not internal names.
3. **Let users undo.** Clear exits, cancel, back and undo; no dead ends.
4. **Be consistent.** Same words, styles and behavior for the same things; follow platform conventions.
5. **Prevent errors.** Good defaults, constraints and confirmations before destructive actions.
6. **Show, do not make users remember.** Options and needed information visible when needed.
7. **Support both new and expert users.** Shortcuts and defaults without getting in the way of beginners.
8. **Keep it focused.** Every element earns its place; remove what competes with the main task.
9. **Help users recover.** Errors explain the problem in plain words and how to fix it.
10. **Provide help in context.** Short help where the question arises.

## Visual hierarchy checks

- One clear focal point per screen, matching the main task.
- Size, weight, color and spacing rank elements in a deliberate order.
- Related items are grouped; unrelated items are separated by space, not only by lines.
- Alignment is consistent; a grid is visible in the structure.
- Body text is readable: size, line length (under about 80 characters) and line height.

## Interaction checks

- Every interactive element looks interactive and has hover, focus, active and disabled states.
- Primary and secondary actions are visually distinct; only one primary action per view.
- Forms show errors next to the field, keep the user's input, and say how to fix the problem.
