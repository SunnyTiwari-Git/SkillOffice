# Browser testing patterns

Written as tool-neutral steps. The names in brackets are the Playwright equivalents; other tools have the same ideas.

## Discover elements on a page

1. Open the page and wait for it to settle (wait for network idle, or for a known heading).
2. Collect all buttons, links and form inputs with their accessible names.
3. Print them as a short list: role, name, whether visible and enabled.
4. Use that list to choose selectors. Prefer role and name (`getByRole('button', { name: 'Sign up' })`), then label text (`getByLabel('Email')`), then visible text, then a test id.

## Test a static HTML file

Open it with a `file://` URL built from the absolute path of the file. No server is needed. Read the HTML first to find selectors; switch to the dynamic approach if content is generated by scripts.

## Capture console errors and failed requests

Before navigating, subscribe to the browser's console messages and failed network requests. After the journey, report every error and failed request with its URL and message. A journey that "passes" with console errors still gets a finding.

## Start a local server safely

- Start only the command the user confirmed (for example `npm run dev`).
- Wait until the port responds before testing, with a time limit (for example 30 seconds), and report a clear error if it never starts.
- Stop the server when testing ends, even if tests failed.
- If the app needs a backend and a frontend, start both and wait for both ports.

## Waiting correctly

- Wait for a condition: an element visible, a URL change, a response received.
- Never use fixed sleeps to "let it load". If a test needs one to pass, the test is flaky; find the condition instead.

## Screenshots as evidence

Take a full-page screenshot at each failure and at the end of each journey. Save them inside the project's test output folder, never in system folders, and reference the paths in the results table.

## Keep tests independent

Each test creates the data it needs and does not rely on another test having run first. Clean up data you created when the tool supports it.
