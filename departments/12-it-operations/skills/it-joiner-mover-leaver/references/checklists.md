# Joiner and leaver checklists

Adapt to the systems the company uses. Each line needs an owner, a time and a way to verify it.

## Joiner

| Item | Verify by |
| --- | --- |
| Identity account created from the role baseline, added to groups | Group membership shows the role's groups only |
| MFA enforced from first sign-in | Sign-in policy shows MFA required |
| Device ordered, enrolled in device management, disk encryption on, updates on | Device appears as compliant |
| Email, chat and calendar | Test message sent and received |
| Role SaaS seats assigned (no admin by default) | Seat list matches the role |
| Password manager personal vault and team vaults for the role | Vault membership matches the role |
| Security basics briefing: phishing, reporting incidents, device care | Acknowledged |
| First-day sign-in session booked | Calendar entry |

## Leaver

| Item | Verify by |
| --- | --- |
| Sign-in disabled at the agreed time | Account shows disabled |
| All sessions revoked, app passwords, API tokens, SSH keys and OAuth grants removed | Session and token lists empty |
| MFA devices and recovery options removed | Security settings empty |
| Mailbox and files preserved for the retention period HR or legal set | Archive or hold in place |
| File, drive, calendar and repository ownership transferred to a named owner | New owner confirmed |
| SaaS seats removed; licenses reported to procurement | Seat lists updated |
| Shared secrets the leaver knew rotated (shared accounts, team vault items, Wi-Fi, door codes) | Rotation logged |
| Device returned, then wiped after data is preserved | Asset record updated |
| Mail forwarding or auto-reply set only as policy allows | Setting confirmed |
| Access to the leaver's data granted only with documented HR or legal approval | Approval reference recorded |

## Immediate or sensitive departure

Disable access first, then complete the rest the same day. Tell cybersecurity (14) if there is any sign of data being taken.
