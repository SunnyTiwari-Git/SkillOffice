# Operations and project management playbooks

Each playbook lists inputs to confirm, the default skill order, when to skip a skill, and what the correction cycle usually fixes. Always follow the core orchestration protocol: plan first, run only what is needed, one correction cycle, one report. Dates and budgets are drafts for confirmation.

## 1. New project kickoff

**Confirm first**: the goal, sponsor, deadline and who set it, team and availability, budget, and methodology (waterfall, agile or hybrid).

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-project-plan | Never |
| 2 | biz-raid-log | Never |
| 3 | biz-capacity-plan | The team is small and fully dedicated, and load is not a question |
| 4 | biz-status-report | The user does not need a reporting template yet |
| 5 | biz-project-review | Never |

**Correction cycle usually fixes**: missing out-of-scope list, deliverables without one accountable owner, dates without estimates, hidden buffer, risks without owners.

**Possible handoffs**: Finance (03) for budget; HR (02) if hiring is needed.

## 2. Weekly status

**Confirm first**: the period, the audience, updates from owners, and the current plan and RAID log.

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-raid-log (update) | No RAID log exists and the user only wants the report |
| 2 | biz-status-report | Never |
| 3 | biz-project-review | Overall status is green |

**Correction cycle usually fixes**: status not matching the evidence, forecast changes without old and new dates, decisions without deadlines.

## 3. Scope change

**Confirm first**: what is requested, by whom, the current baseline and who can approve.

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-change-request | Never |
| 2 | biz-raid-log (update) | No RAID log exists |
| 3 | biz-project-review | The change is small and does not touch the critical path |

**Correction cycle usually fixes**: impact stated as "everyone" or "some delay", a single option only, missing rollback, missing approver.

## 4. Process documentation

**Confirm first**: the process name, its owner, who does each part, and existing documents.

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-process-documentation | Never |

**Correction cycle usually fixes**: steps without owners, missing exceptions, missing controls for money, access or data. Gaps that need redesign go to the report as suggestions for process improvement.

## 5. Process improvement

**Confirm first**: the goal (speed, quality, cost, experience, compliance), the current steps and any measurements.

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-process-documentation | A current-state map or SOP already exists |
| 2 | biz-process-improvement | Never |
| 3 | biz-project-review | The changes are quick wins with no implementation plan |

**Correction cycle usually fixes**: improvements that skip the bottleneck, benefits without arithmetic, removed controls without an approver, no baseline metric.

**Possible handoffs**: IT Operations (12) for tool changes; HR (02) when roles change.

## 6. Project health check

**Confirm first**: the documents available (plan, schedule, RAID log, recent status) and the concern.

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-project-review | Never |

The correction cycle applies only if the user asks for the fixes to be made to the plan.

## 7. Office and administration

**Confirm first**: the task, location, headcount, dates, budget and building rules.

| Order | Skill | Skip when |
| --- | --- | --- |
| 1 | biz-facilities-admin | Never |
| 2 | biz-project-plan | The task is a routine checklist rather than a project such as an office move |

**Possible handoffs**: IT Operations (12) for equipment and access; Procurement (17) for purchasing; Finance (03) for budget; HR (02) for staff communications.
